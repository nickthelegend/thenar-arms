# Reconstruction decisions

The accepted result is summarized in final_report.md. Raw accepted and rejected evidence is retained in solidworks/evidence, solidworks/checkpoints and verification.

1. Preserve current R3 follower and L1 leader revisions. Upstream STEP files describe a different revision and were not substituted. Current generator dimensions, meshes and assembly transforms define the modified geometry. All 330 original files match their saved hashes.
2. Use the running SolidWorks 2026 SP4.1 COM API through a task-local stdio MCP bridge. No permanent plugin or network listener was installed. Native parts, assemblies, datums and mate features are saved on disk.
3. Preserve the unrelated SolidWorks_Test_Plate.SLDPRT. It had no unsaved edits before memory-exhausted application recovery and was reopened unchanged. Incremental mate saves and cleared undo history enabled the large faceted leader build to recover from checkpoints.
4. Rebuild simple hardware with native sketches/extrusions/cuts. Preserve complex modified prints as solid base geometry with native joint datums rather than claiming recovered manufacturing feature histories. Disable sketch inference and verify datum endpoints numerically.
5. Use explicit COM VT_ARRAY|VT_R8 transform arrays and assert readback: plain Python lists silently produced identity. Convert source intrinsic XYZ rotations and URDF extrinsic xyz RPY explicitly. SOURCE_Z_UP changes the camera only; source native coordinates are preserved.
6. Reject automatic repairs that materially alter surfaces, even if volume is nearly unchanged. Accept partitioned CAD only after kernel, volume, bounds and bidirectional exterior checks. The follower forearm has three solid partitions; leader base and forearm each have four. The leader forearm requires a disclosed 0.00001 mm internal separation at Z=16.2 mm.
7. Preserve source zero-thickness artifacts. Omitting trigger flaps caused about 0.967 mm surface error despite negligible volume change and was rejected. Three trigger sheets and eight forearm surface facets preserve them without invented thickness. They are excluded only from volumetric collision calculations.
8. Ground only each base. Lock hardware to its source rigid group. Each joint uses axis-collinearity, axial-plane and limit-angle mates. Native angle equals 90 degrees plus logical angle. Source software limits remain labelled separately from unknown physical safe limits.
9. Accept motion only after native mate solving and measured component-transform comparisons. Follower API drag probes and a leader direct-dimension branch trial failed and were rejected. Recover saved assemblies and use mate-definition changes for accepted motion. Independently read back stored configurations; failed trials do not count as passes.
10. A six-DOF constraint-matrix result is CALCULATED from native mate topology and measured frames, not a SolidWorks kernel DOF or mouse-drag diagnostic. Discrete collision checks are not swept-motion certification. Report intentional shaft/horn engagements and small overlaps instead of silently excluding pairs.
11. Preserve original workspace collisions. Some source-valid angle commands penetrate the table. The inherited leader 72-pose report and current CAD results remain separate evidence; do not redesign geometry to remove their limitations.
12. Do not fabricate physical mass/COM/inertia, effort, friction, damping, armature or contact parameters. Unit-density CAD integrals are geometric preparation. PETG/25% gyroid/four-wall print settings and a plate total cannot supply link mass. A genuine TowerPro 55 g reference is not automatically applicable to generic MG996R units.
13. Compare Xacro/URDF and MuJoCo forward kinematics with the same 28 canonical joint vectors. Reject importer-inferred masses. The dedicated MJCF disables inferred inertia and deliberately rejects physical-model loading until supported inertias exist. ROS 2/RViz and Isaac were not found in the accessible runtime; prepare handoffs without claiming execution or fabricating USD.
14. Verify source-envelope box/cylinder unions for servo collision geometry. Retain exact concave print/horn meshes for geometric inspection. Fine convex decomposition was impractically fragmented and was not accepted. Validated dynamic-contact print proxies remain outstanding.

## Final range-mate correction

The delivered-mate readback gate caught that editing IAngleMateFeatureData.Angle in SolidWorks 2026 collapses its lower/upper bounds to the current angle unless the range properties are reapplied. Earlier fixed-angle pose tests established kinematics but did not establish free rotational mobility. Those files are checkpointed as fixed-angle pose evidence and superseded by the range-mate regression.

A subsequent saved-configuration test rejected that intermediate conversion workflow: marking the limit dimension driven allowed its bounds to shift during movement. The accepted construction creates fresh IAngleMateFeatureData through CreateMateData/CreateMate, provides the two datum-plane entities explicitly, and verifies the native MateLimitPlanarAngleDim feature type. Its default driving dimension state is retained. Six separate standard angle holders position the joints and store the named configurations; they are suppressed in FREE_MOTION. Moving the holders then leaves the actual range bounds unchanged. Reacquiring COM objects after feature modification remains necessary. Final acceptance requires every component transform, min/max readback, configuration round trips and independent saved-file reopen checks.

Use real_limit_mates.py, validate_real_limits.py or set_robot_pose.py for future pose work. Legacy fixed-angle or drag trial scripts are retained for traceability and must not be used over a delivered master. The task-local MCP bridge now exposes set_robot_joint_pose with source-bound validation and post-solve checks. No original geometry was changed by this correction.

API reference: https://help.solidworks.com/2026/English/api/sldworksapi/SolidWorks.Interop.sldworks~SolidWorks.Interop.sldworks.IAngleMateFeatureData~IsAdvancedMate.html . Driven mate UI reference: https://help.solidworks.com/2026/english/SolidWorks/Sldworks/t_assembly_mate_controller_drag_position.htm .

Explicit parent joint-axis references prevent ambiguous angle solutions during configuration changes. Standard snapshot angle holders and active range mates can produce redundant-mate warnings together, so snapshot configurations activate the holders and suppress ranges; FREE_MOTION activates ranges and suppresses holders. Every canonical motion regression is measured after the holders are released and all six native ranges are active.

The expected native status-2 gate was rejected as an inappropriate DOF test: with a genuine Limit Angle active, GetConstrainedStatus returned 3; suppressing that range alone returned 2, restoring it returned 3. We record this observation without treating the component-status enum as a DOF count. Full-range mate-solved movement, exact active mate/entity topology and the calculated constraint nullspace are the articulation checks. API drag attempts remain rejected; mouse dragging is explicitly unverified.

For the follower's inherited angle dimensions, a stored numeric value could match the requested value while the current configuration remained on an alternate geometric solution. The supported helper now writes all six values explicitly into the active named configuration rather than skipping apparently unchanged dimensions. Explicit axis references then resolve the wrist/jaw branches; all final acceptance poses are measured afterward. No arbitrary component transforms are assigned to obtain accepted poses.
